Nano Tracker

Sharing one catalogue across computers

You only need this if several of you work together. If you use Nano Tracker on a single computer, everything is already fine and this page is not for you.

What do you need to do?

Pick the line that matches your situation: we will show you only the steps you need.

Creating the database on a NAS

Seven steps. The first four on the NAS, the last three in Nano Tracker.

1

Open the NAS in your browser, as if it were a website. The address is the NAS number followed by :5000 - for example http://192.168.1.101:5000 - and log in with the NAS administrator account.

I do not know my NAS address

Four ways, easiest first:

  1. With your NAS maker's own tool. Synology: finds.synology.com, opens in the browser and finds the NAS by itself. QNAP: Qfinder Pro. Other brands (ASUSTOR, UGREEN, TerraMaster, Western Digital and so on) have an equivalent tool, usually called finder or discovery.
  2. From Windows: open File Explorer and click Network in the left column. The NAS appears under its name; right-click it and choose Properties: the address is there.
  3. From a Mac: in Finder open Go → Connect to Server (or ⌘K). If you have used the NAS before, the recent servers list shows something like smb://192.168.1.101: the number is what you need. Otherwise press Browse to see the devices on your network.
  4. From your router: in the list of connected devices. The most awkward way, but it always works, whatever the brand.

The address is four numbers separated by dots, like 192.168.1.101.

I typed the address and nothing opens

Try :5001 instead of :5000, writing https rather than http - some NAS units only accept that: https://192.168.1.101:5001

2

Open Package Center, search for MariaDB 10 and press Install.

Brands only change the names. On QNAP the Package Center is called the App Center; on other brands it is the App Store or App Management. Any NAS that can install MariaDB will do: we describe the Synology clicks because it is the most widespread, but the steps are the same everywhere.

3

During installation it asks you to choose a password. This is the database administrator password, and it is not the one you use to log into the NAS: it is something new, you choose it.

Write it down on paper. You need it at step 7 and the NAS will never show it to you again. Lose it and you start over.

4

Once it has finished, open MariaDB 10 in Package Center and press Open.

This is the step where nearly everyone gets stuck. In the window that appears, tick «Enable TCP/IP connection» and press Apply. Without that tick the NAS answers nobody, and it looks like nothing works.

Next to the tick box there is a number: that is the database port, usually 3306. Note it down.

Hold on: earlier it was 5000, now 3306. Why?

They are two different ports with nothing to do with each other. 5000 is only for you, to open the NAS in a browser. 3306 is the one Nano Tracker will use to talk to the database. It is the second one you need.

If you see 3307 next to the tick box instead of 3306, that is fine: write that one down. It happens when an older MariaDB is also installed on the NAS.

5

Go back to Nano Tracker. At the bottom of the left-hand menu there is the Settings gear: open it and scroll to the Database box. Press the + next to «Connection» and choose «Create a new shared database».

6

Press «Search for MariaDB on the network». If your NAS shows up, click it: from there the app does the rest.

Not finding it? Open «I would rather type the address myself», type the NAS address, leave the port empty and press Check. If it stays red, see if something does not work below.

7

It asks for the password from step 3, then a name and a password for the new database. Press Create and connect.

Done. The other computers in the studio do not need any of this: on this computer open Settings → Database → Copy Credentials, send those details to your colleagues, and they follow the third route on this page — the one about connecting.

Creating the database on a computer

Pick a Windows PC that stays switched on while the others work. Six steps.

1

On that computer go to mariadb.org/download and download MariaDB for Windows.

The page asks me things, what do I pick?

Leave the version it offers you (that is the recommended one). Then choose Windows as the operating system and MSI Package as the file type. The architecture is x86_64, which is what every computer of the last fifteen years uses.

Download it and double-click: the file ends in .msi.

2

Run it and continue until it asks you for a password.

3

Type a password and confirm it. Write it down: you will need it at the end.

On the same page, tick the box «Enable access from remote machines for 'root' user». It is a long line of text, but it is the one that lets the other computers connect. Without it, nothing works.

4

Continue, leaving everything as it is, and finish the installation.

5

On that computer open the Start menu, type cmd, open the Command Prompt and type ipconfig. You want the IPv4 Address line: a number like 192.168.1.50. Note it down.

Windows blocks incoming connections. On that PC open Windows Defender Firewall → Advanced settings → Inbound Rules → New Rule → Port → TCP → 3306 → Allow. It is the equivalent of the NAS tick box: without it, the others cannot reach it.

6

In Nano Tracker open the Settings gear at the bottom of the left-hand menu and scroll to the Database box. Press the +, choose «Create a new shared database» and press «Search for MariaDB on the network».

It then asks for the password from step 3 and a name for the new database. Press Create and connect.

If the search does not find the computer, open «I would rather type the address myself» and type the number from step 5.

Done. Send the details to the other computers with Settings → Database → Copy Credentials: all they need is the third route on this page.

Connecting to a database that already exists

Three steps, two minutes.

1

Ask whoever created it to send you the details. On their computer they are in Settings → Database → Copy Credentials: one button copies everything at once, so nobody has to type anything out and nobody gets it wrong.

What exactly do they need to send me?

Five things: the address (like 192.168.1.101), the port (like 3306), the database name, the user name and the password.

The Copy Credentials button puts them all on the clipboard together: they just paste them into a message.

2

On your computer open the Settings gear at the bottom of the left-hand menu, scroll to the Database box, press the + and choose «Connect to an existing shared database».

3

Fill the fields with what you were sent, press Test Connection and then Save Connection.

Done. From now on you see the same catalogue as your colleagues: the disks they have already catalogued show up for you too, even if you have never plugged those disks into this computer.

If something does not work

«No answer» when you press Check. Look at these, in this order:

  • the «Enable TCP/IP connection» tick box on the NAS (or the firewall rule, if it is a Windows PC);
  • the port: on some NAS units it is not 3306 but 3307. The right number is written in the MariaDB window on the NAS;
  • the address: make sure it really is the NAS or the PC.

«Answers but refuses this computer». The database is there and the port is right, but it will not accept connections from outside. On many NAS units the administrator can only log in from the NAS itself. Ask whoever runs your network, or create it on the NAS with phpMyAdmin using these three lines (change only the password):

  • CREATE DATABASE nano_tracker CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  • CREATE USER 'nano_tracker'@'%' IDENTIFIED BY 'your-password';
  • GRANT ALL PRIVILEGES ON nano_tracker.* TO 'nano_tracker'@'%';

Then come back here and follow the third route, the one about connecting.

Do I lose what I have already catalogued? No. The catalogue stays on your computer and the app copies it across to the shared one: nobody starts from scratch.

Does the NAS have to stay on? Only while you work. If it does not answer, Nano Tracker falls back to the catalogue on your computer and never blocks you.

Is it safe? The database stays inside your own network. Do not forward that port on your router — there is no need.
